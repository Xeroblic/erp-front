## Tema: PR #191 — correcciones tras revisión (selector de clientes compartido)

**Rama:** `feat/cotizaciones-selector-clientes-compartido`

- **[fix]** `CreateCustomerSaleModal`: se agregó una validación cruzada en el schema de Yup que exige al menos uno de `billing_company` o `contact_name`, igual que el `hasUsableName` de `SubsidiaryCustomerSalesController`. Sin esto, un alta con RUT + email pero ambos campos vacíos creaba un cliente que el backend descarta de toda búsqueda con `strict=true` (el default de `fetchCustomersOverviewThunk` y `fetchCustomersListOverviewThunk`), dejándolo inalcanzable desde la interfaz. El test cruzado se extrajo a una función de módulo (`hasUsableName`) para que `this.createError` no dispare `react/no-this-in-sfc` al quedar anidado dentro del componente.
- **[test]** Se ajustó el test que antes guardaba con ambos campos vacíos (ahora completa Contacto) y se agregó un test que confirma que el envío se bloquea, sin llamar al backend, cuando Empresa y Contacto llegan vacíos.
- **[fix]** `CreateQuotationModal` y `EditQuotationModal`: se reemplazó el fallback `?? 1` de `subsidiary_id` por `?? 0` (falsy) y se agregó una guarda explícita en el `onSubmit` de cada modal (mismo aviso que `useQuotationsManager.createQuotation`), para que el código deje de contradecir lo que el PR y esta bitácora afirman sobre no defaultear a la subsidiaria 1.
- **[fix]** `CreateCustomerSaleModal`: segunda pasada de revisión — el bloqueo de `nombre-utilizable` era silencioso (`Input` no pinta `invalidFeedback`, sólo el borde rojo) y el rótulo del campo Empresa decía «(opcional)», lo contrario de lo que exige el schema cuando Contacto viene vacío. Se quitó «(opcional)» del rótulo y se envolvió el `Input` de Empresa en `Validation` para que el mensaje "Ingresa Empresa o Contacto" llegue al DOM, no sólo el borde.
- **[test]** Se agregó una aserción sobre el texto del error en el test que bloquea el envío sin Empresa/Contacto, y un test nuevo que confirma que el rótulo ya no dice «(opcional)».
- **Referencia:** [PR #191](https://github.com/Xeroblic/erp-front/pull/191).
