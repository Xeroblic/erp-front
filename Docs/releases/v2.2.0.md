# Zentria ERP — v2.2.0

**Fecha de lanzamiento:** 10 de agosto de 2026  
**Versión anterior:** v2.1.0

## Resumen

Zentria ERP v2.2.0 incorpora el dominio financiero de **Pagos Diferidos** y la gestión de **Cartera de Crédito**. La versión permite administrar el ciclo completo de documentos, abonos y comprobantes por subsidiaria, e integra perfiles de crédito en la ficha de clientes.

El release también corrige el onboarding mediante invitaciones, mejora la presentación de roles y permisos usando los nombres entregados por el backend y refuerza la protección del rol `super-admin`.

Esta versión reúne los cambios integrados en `develop` después de v2.1.0 mediante los PR **#106, #108, #118, #124 y #130**.

---

## Nuevas funcionalidades

### Gestión integral de Pagos Diferidos

Se incorpora un módulo completo para administrar documentos de pago diferido durante todo su ciclo de vida.

- Dashboard con indicadores, filtros y tabla operativa.
- Creación y edición de documentos asociados a clientes y subsidiarias.
- Registro de abonos y comprobantes.
- Visualización de detalle, ítems, actividad y saldos.
- Anulación, cierre manual y eliminación bajo permisos explícitos.
- Estados de carga, error y confirmación para las operaciones financieras.
- Actualización coordinada de lista, resumen, detalle y cartera después de cada mutación.
- Aislamiento de respuestas obsoletas al cambiar de subsidiaria o entidad.
- Conservación del borrador cuando el backend rechaza una operación.
- Uso del total y cupo autoritativos informados por el backend.

PR: [#130 — Gestión integral de pagos diferidos](https://github.com/Xeroblic/erp-front/pull/130)

### Cartera y perfiles de crédito

El nuevo flujo financiero se complementa con información de crédito por cliente.

- Vista de cartera de crédito por subsidiaria.
- Perfil de crédito integrado en el detalle del cliente.
- Edición de cupo, condiciones y datos de cobranza.
- Bloqueo de nuevos pagos diferidos para perfiles suspendidos.
- Recarga de la cartera después de operaciones que modifican los saldos.
- Soporte para correo de cobranza.

PR: [#130 — Gestión integral de pagos diferidos](https://github.com/Xeroblic/erp-front/pull/130)

### Mejoras en la gestión de clientes

- Alta y edición rápida de clientes desde los flujos comerciales.
- Mapeo de errores de validación del backend a campos específicos.
- Normalización de respuestas de clientes.
- Validación de subsidiaria activa antes de crear o editar.
- Prevención de duplicados y descarte de mutaciones obsoletas.
- Mejoras de jerarquía visual en el detalle del cliente.

PR: [#130 — Gestión integral de pagos diferidos](https://github.com/Xeroblic/erp-front/pull/130)

## Seguridad, roles y permisos

### Etiquetas administradas por el backend

- Roles y permisos muestran `display_name` como fuente de verdad.
- Los slugs canónicos se mantienen en los payloads enviados a la API.
- Se agregan fallbacks locales cuando el catálogo remoto no está disponible.
- Los catálogos se cargan automáticamente en las vistas que solo reciben slugs.
- Se preservan siglas y capitalización definidas por administración.

### Protección de `super-admin`

- La autorización valida el slug canónico del rol y no su etiqueta visible.
- Se evita que usuarios no administradores asignen `super-admin` desde invitaciones.

PR: [#118 — Nombres de roles y permisos y filtro de super-admin](https://github.com/Xeroblic/erp-front/pull/118)

## Activación de usuarios

Se corrigió un crash que impedía mostrar el formulario de creación de contraseña en `/usuarios/activar/:token`.

- Los hooks se ejecutan antes de cualquier retorno condicional.
- El estado inicial evita mostrar brevemente un formulario incompleto.
- El fallback global de errores deja de depender del contexto Redux.
- Los mensajes se resuelven por estado HTTP y no exponen detalles técnicos del backend.
- Se distinguen enlaces inválidos, invitaciones usadas o expiradas, errores de validación, fallas del servidor y problemas de conexión.
- Se agregaron pruebas de regresión para el crash y los estados de error.

PR: [#124 — Corrección de activación de usuario](https://github.com/Xeroblic/erp-front/pull/124)

## Calidad y arquitectura

### Dominio financiero

- Contratos TypeScript para pagos diferidos y perfiles de crédito.
- Servicio HTTP dedicado.
- Estado Redux, thunks y selectores del dominio.
- Rutas y navegación protegidas por permisos.
- Utilidades para normalización de errores del backend.

### Cobertura automatizada

La entrega de Pagos Diferidos incluye **19 suites y 143 pruebas focalizadas** para formularios, drawers, tablas, acciones, servicios, thunks y reducers. También se incorporaron regresiones para activación de usuarios, perfiles de crédito, clientes y componentes compartidos. En la preparación del release, la suite completa aprobó **64 archivos y 384 pruebas**.

Las verificaciones registradas en los PR de origen incluyen:

- TypeScript sin errores mediante `tsc --noEmit`.
- Build de producción generado correctamente.
- Suite completa: 64 archivos y 384 pruebas aprobadas.
- Suite focalizada de Pagos Diferidos: 143 pruebas aprobadas.
- Build de producción aprobado para los cambios de roles, permisos y activación.

## Compatibilidad y migración

- No se introducen cambios incompatibles conocidos en las interfaces públicas del frontend.
- El módulo de Pagos Diferidos requiere los endpoints, permisos y contratos correspondientes en el backend.
- Los permisos y roles continúan enviándose a la API mediante sus slugs canónicos.

## Deuda conocida no bloqueante

- El smoke manual autenticado de todos los roles, permisos y subsidiarias del nuevo módulo permanece pendiente.
- Algunas pruebas de componentes pueden emitir advertencias `act(...)` sin provocar fallos.
- El backend puede responder `500` para invitaciones ya usadas o expiradas; el frontend ya oculta el detalle técnico, pero el backend debería devolver `410`.
