# Zentria ERP — v2.1.0

**Fecha de lanzamiento:** 22 de julio de 2026
**Versión anterior:** v2.0.0

## Resumen

Zentria ERP v2.1.0 incorpora nuevas funcionalidades para revisiones técnicas, integraciones WooCommerce, cotizaciones
y ventas. También incluye una refactorización completa del módulo de Bodegas, mejoras en la tabla de productos y una
nueva infraestructura automatizada de pruebas.

Este release contiene los cambios fusionados mediante los PR comprendidos entre el **#93 y el #102**, más el PR **#105**
con la preparación del release (versionado y notas).

---

## Nuevas funcionalidades

### Revisiones técnicas: galería de fotografías

Se incorporó una galería de fotografías asociada a cada ítem de revisión técnica.

- Nueva sección **Galería** en el segundo paso de la revisión.
- Disponible para Notebook, Desktop, AIO, Docking y Monitor.
- Carga múltiple mediante selector de archivos o arrastrar y soltar.
- Validación de imágenes JPG, JPEG, PNG y WebP.
- Tamaño máximo de 8 MB por imagen.
- Límite de 20 fotografías por carga.
- Visualización mediante miniaturas.
- Lightbox para visualizar fotografías en resolución completa.
- Eliminación de imágenes según los permisos del usuario.
- Modo de solo lectura para revisiones aprobadas.
- Normalización de las respuestas del backend para mantener un contrato único en el frontend.

PR: [#98 — Galería de fotos por ítem](https://github.com/Xeroblic/erp-front/pull/98)

### Acceso rápido a la Galería

Se agregó un botón **Galería** en el subheader del módulo de revisiones técnicas.

- Acceso directo a la galería desde diferentes pasos de la revisión.
- Si el usuario está en otro paso, el sistema navega automáticamente al formulario y abre la galería.
- El botón se deshabilita cuando todavía no existe un ítem asociado.
- Se evita saltar secciones durante la creación de una revisión nueva.
- El acceso permanece habilitado para revisiones reabiertas.
- Disponible en revisiones de solo lectura.
- Control de navegación de una sola ejecución para evitar reaperturas inesperadas durante el montaje del formulario.

PR: [#102 — Acceso rápido a Galería desde el subheader](https://github.com/Xeroblic/erp-front/pull/102)

### Segunda batería en notebooks

Las revisiones técnicas de notebooks ahora permiten registrar equipos con una segunda batería.

- Nuevo campo para indicar si el notebook incluye una segunda batería.
- Registro de estado, condición y porcentaje de la batería secundaria.
- Uso de las mismas opciones disponibles para la batería principal.
- Comportamiento diferenciado para equipos Dell y otras marcas.
- Limpieza automática de los campos al desactivar la segunda batería.
- Validaciones condicionales mediante Yup.
- Compatibilidad con el sistema de guardado automático.

PR: [#97 — Segunda batería en notebooks](https://github.com/Xeroblic/erp-front/pull/97)

### Descarga de cotizaciones en Excel

Las cotizaciones ahora pueden descargarse en formato Excel además del PDF existente.

- Nuevo menú con opciones para descargar en PDF o Excel.
- Generación de archivos `.xlsx` utilizando la plantilla corporativa.
- Inclusión de datos de empresa, subsidiaria, cliente, productos, condiciones, totales y datos bancarios.
- Conservación de estilos y combinaciones de celdas de la plantilla.
- Inserción automática de filas cuando una cotización supera la capacidad original de la plantilla.
- Reubicación automática de totales y pie de página.
- Carga diferida de las dependencias utilizadas para generar el archivo.

PR: [#95 — Descarga de cotización en Excel además de PDF](https://github.com/Xeroblic/erp-front/pull/95)

### Papelera y restauración de integraciones

Se reemplazó la eliminación permanente de integraciones WooCommerce por un sistema reversible.

- Implementación de soft-delete para integraciones.
- Nueva vista de papelera con selector entre integraciones activas y eliminadas.
- Contador de integraciones presentes en la papelera.
- Restauración de integraciones junto con sus productos vinculados y configuraciones.
- Detección de tiendas previamente eliminadas al crear una integración.
- Sugerencia automática para restaurar una integración en lugar de duplicarla.
- Manejo de conflictos de unicidad durante la restauración.
- Nuevo modal para rotar claves, reemplazando la confirmación nativa del navegador.
- Controles de permisos para crear y eliminar integraciones.
- Prevención de registros duplicados después de una restauración.
- Flujo seguro de reactivación: primero restaura la integración original y después elimina el reemplazo.

PR: [#100 — Soft-delete, papelera y restauración de integraciones](https://github.com/Xeroblic/erp-front/pull/100)

## Productos y sistema visual

### Modularización de la tabla de productos

`ProductsTableV2`, anteriormente concentrada en un archivo de aproximadamente 990 líneas, fue dividida en componentes
especializados.

- Separación de la tabla, columnas, celdas, variantes y utilidades.
- Una celda independiente para producto, precio, WooCommerce, marca, estado, publicación, categorías y acciones.
- Extracción de la tabla expandible de variantes.
- Corrección del uso de hooks dentro de definiciones inline de columnas.
- Conservación del contrato público existente para evitar cambios en sus consumidores.

### Corrección y mejora de Badge

- `Badge` ahora utiliza `forwardRef`.
- Integración segura entre el ref externo y el ref interno utilizado por GSAP.
- Eliminación del warning de React al utilizar badges dentro de tooltips.
- Mejoras visuales en badges de estados, WooCommerce, categorías y tipos de producto.
- Hover más claro y consistente para filas expandibles.
- Compatibilidad visual con temas claro y oscuro.

PR: [#93 — Modularización de ProductsTableV2 y corrección de Badge](https://github.com/Xeroblic/erp-front/pull/93)

## Ventas

### Corrección de eliminación de ventas

Se corrigió el botón de eliminación de la lista de ventas, que anteriormente abría el detalle en lugar de ejecutar la
acción correspondiente.

- Nuevo modal de confirmación.
- Visualización del número de venta que se eliminará.
- Prevención de envíos duplicados mientras la operación está en curso.
- Ejecución del thunk de eliminación existente.
- Actualización de la lista al finalizar.
- Bloqueo de la eliminación para ventas cerradas.
- Bloqueo de la eliminación cuando el inventario está finalizado.
- Tooltip explicativo cuando la acción no está disponible.

PR: [#94 — Corrección del botón de eliminar venta](https://github.com/Xeroblic/erp-front/pull/94)

## Notificaciones

Se simplificó la interacción con las notificaciones para abrir su detalle con un solo clic o toque.

- Eliminación de la lógica anterior de doble toque.
- Detección de un toque limpio mediante eventos de puntero.
- Apertura inmediata del detalle.
- Conservación del gesto hacia la derecha para marcar como leída.
- Conservación del gesto hacia la izquierda para archivar.
- Corrección de la interacción afectada por `setPointerCapture`.

PR: [#96 — Abrir detalle de la notificación con un solo clic](https://github.com/Xeroblic/erp-front/pull/96)

## Refactor del módulo de Bodegas

Se realizó una refactorización integral del módulo para alinearlo con la arquitectura estándar de Zentria ERP.

### Arquitectura

- Separación entre lógica, vistas presentacionales y ensambladores.
- Nuevos hooks `useBodegas` y `useBodegaDetail`.
- Uso de `useCurrentBranch` para resolver la sucursal actual.
- Formularios Formik centralizados en los hooks.
- Esquemas Yup unificados.
- Eliminación de hooks, interfaces y componentes obsoletos.

### Type safety

- Eliminación de más de 44 usos de `any`.
- Manejo de excepciones mediante `unknown`.
- Nuevo helper para extraer errores del API.
- Tipado estricto de tablas, bodegas y respuestas del backend.
- Eliminación de casts innecesarios en las columnas.

### Autorización

- Botones protegidos para crear, editar y eliminar bodegas.
- Protección del modo de edición del detalle.
- Incorporación de protección en la ruta de detalle.

### Manejo de errores

- Errores procesados mediante códigos y campos del backend.
- Manejo específico de bodegas que contienen productos.
- Manejo de errores al adjuntar o retirar productos.
- Indicador de carga mientras se obtiene el detalle.
- Eliminación de capturas de errores silenciosas y mensajes de depuración.

### Rendimiento y experiencia de usuario

- Selectores Redux atomizados.
- Resultados de hooks memoizados.
- Opciones de comunas memoizadas.
- Búsqueda de bodegas por nombre y código.
- Subheader alineado visualmente con el módulo de Cotizaciones.
- Colores y acciones unificados para guardar, actualizar, cancelar, eliminar y habilitar edición.

PR: [#101 — Refactor integral del módulo de Bodegas](https://github.com/Xeroblic/erp-front/pull/101)

## Infraestructura de pruebas

Se reparó y amplió la infraestructura automatizada de pruebas.

### Configuración

- Vitest fijado en una versión compatible con Vite 5.
- Configuración de pruebas con ambiente `jsdom`.
- Incorporación de polyfills para APIs no disponibles en `jsdom`.
- Integración de matchers de React Testing Library.
- Nuevas utilidades para renderizar componentes con Redux.
- Store de integración con slices reales y MSW.

### Pruebas unitarias

Se agregaron pruebas para hooks de interfaz, autorización y lógica de negocio, incluyendo:

- `useCurrentBranch`
- `useAuthorization`
- `useServerPagination`
- `useGeoSelector`
- `useOrgContextSwitcher`
- `useCompanyManager`

### Pruebas de integración

Se agregaron pruebas para:

- Listado, creación, aprobación, conversión y eliminación de cotizaciones.
- Paginación, filtros, eliminación y totales de ventas.
- Inicio de sesión, perfil, permisos y cierre de sesión.
- Normalización de productos WooCommerce.
- Soft-holds, variantes y estadísticas de productos.
- Caché, deduplicación, invalidación y normalización de `ApiService`.

### Pruebas end-to-end

- Protección de rutas sin sesión.
- Inicio de sesión exitoso.
- Manejo de credenciales inválidas.
- Flujo completo de conversión de cotización a venta.
- Servidor de pruebas aislado para evitar conexiones con ambientes reales.

### Resultado

- 32 archivos de prueba.
- 168 pruebas de Vitest aprobadas.
- 4 pruebas de Playwright aprobadas.
- TypeScript sin errores.

PR: [#99 — Suite de tests unitarios, integración y E2E](https://github.com/Xeroblic/erp-front/pull/99)

## Consideraciones de actualización

- La segunda batería requiere que la migración backend `ZB-100` esté desplegada y que el endpoint de actualización
  acepte sus cuatro campos.
- La galería requiere los endpoints para listar, subir y eliminar fotografías de revisiones técnicas.
- La eliminación de ventas depende de la implementación de `SubsidiarySalesController@destroy` en el backend.
- La restauración de integraciones requiere soporte backend para soft-delete, restauración y conflictos de unicidad.
- El módulo de Bodegas depende de códigos y campos de error estructurados enviados por el backend.
